# فورآپ (ForApp)

اپ اندروید که پیامک واریز بانک را روی گوشی فروشگاه می‌خواند و به یک یا چند وبهوک می‌فرستد تا ربات فروش، پرداخت را با سه رقم آخر مبلغ پیدا کند.

## چرا سبک و کم‌مصرف است

- **هیچ سرویسی در پس‌زمینه روشن نمی‌ماند.** اندروید فقط وقتی پیامک می‌رسد اپ را بیدار می‌کند.
- **بدون هیچ کتابخانه‌ی جانبی.** فقط خود اندروید (SQLite، JobScheduler، HttpURLConnection). کد جاوا است و فقط فونت وزیرمتن کنارش است.
- **سریع:** پیامک همان لحظه‌ی دریافت، هم‌زمان به همه‌ی مقصدها فرستاده می‌شود.
- **خیال راحت:**
  - هر پیامک قبل از ارسال در دیتابیس ذخیره می‌شود. اگر اینترنت نباشد یا سرور جواب ندهد، در صف می‌ماند و با فاصله‌ی ۱۵ ثانیه، ۳۰ ثانیه، ۱ دقیقه و … (تا ۳۰ دقیقه) دوباره فرستاده می‌شود.
  - بی‌اینترنتی جزو تلاش‌ها حساب نمی‌شود؛ وقتی اینترنت برگردد، صف خالی می‌شود.
  - بعد از خاموش و روشن شدن گوشی یا آپدیت اپ، صف خودش ادامه پیدا می‌کند.
  - هر درخواست هدر `Idempotency-Key` دارد، پس ارسال دوباره روی سرور پرداخت تکراری نمی‌سازد.
  - اگر یک ارسال بعد از همه‌ی تلاش‌ها نرسد، اعلان می‌آید و در لاگ قرمز می‌شود و با یک لمس دوباره فرستاده می‌شود.
- **امن:** فقط پیامک فرستنده‌هایی که برای بانک‌ها تعریف کرده‌اید خوانده می‌شود. پیامک‌های شخصی ذخیره نمی‌شوند، و یک پیامک «واریز» جعلی از یک شماره‌ی معمولی پرداختی را تأیید نمی‌کند.

## ساخت APK

این پروژه یک پروژه‌ی استاندارد Gradle است (minSdk 26 یعنی اندروید ۸ به بالا، targetSdk 35).

**با Android Studio:** پوشه را باز کنید و `Build › Build APK(s)` را بزنید.

**با خط فرمان** (JDK 17 و Android SDK نصب باشد):

```
./gradlew testDebugUnitTest assembleRelease
```

خروجی در `app/build/outputs/apk/release/` است.

**با GitHub:** اگر پروژه را در یک مخزن GitHub بگذارید، فایل `.github/workflows/build.yml` با هر push خودش APK را می‌سازد و در بخش Actions برای دانلود می‌گذارد.

### کلید امضا

برای اینکه نسخه‌های بعدی روی نسخه‌ی قبلی نصب شوند، همیشه با یک کلید امضا کنید:

```
keytool -genkeypair -v -keystore forapp.jks -alias forapp -keyalg RSA -keysize 2048 -validity 10000
```

بعد کنار `settings.gradle` یک فایل `keystore.properties` بسازید:

```
storeFile=forapp.jks
storePassword=...
keyAlias=forapp
keyPassword=...
```

این دو فایل در git نمی‌روند. اگر نباشند، APK با کلید دیباگ امضا می‌شود که برای آزمایش کافی است.

## راه‌اندازی روی گوشی

۱. APK را نصب کنید. اگر اندروید ۱۳ یا بالاتر است و هنگام دادن اجازه‌ی پیامک پیام «تنظیمات محدودشده» آمد، از «اطلاعات برنامه» در منوی سه‌نقطه‌ی بالا گزینه‌ی «اجازه دادن به تنظیمات محدودشده» را بزنید و دوباره اجازه دهید.
۲. در صفحه‌ی اصلی، نوارهای قرمز بالا را یکی‌یکی حل کنید:
   - اجازه‌ی پیامک
   - خاموش کردن بهینه‌سازی باتری (مهم: بدون آن، در حالت خواب گوشی ارسال‌ها دیر می‌شوند)
   - افزودن مقصد
   - تنظیم فرستنده‌ی بانک‌ها
۳. در «بانک‌ها و فرستنده‌ها» روی هر بانک بزنید و با «انتخاب از پیامک‌های اخیر» شماره‌ی فرستنده‌ی واقعی بانک را انتخاب کنید.
۴. در «مقصدها» آدرس وبهوک و کلید API را وارد کنید، بانک‌های آن مقصد را انتخاب کنید و «ارسال آزمایشی» را بزنید.

روی گوشی‌های شیائومی، هواوی، اوپو و ویوو، در تنظیمات گوشی «اجرای خودکار» (Autostart) را هم برای فورآپ روشن کنید و آن را از «پاک‌سازی حافظه» مستثنی کنید.

## آنچه به وبهوک فرستاده می‌شود

`POST` با `Content-Type: application/json` و این هدرها:

| هدر | مقدار |
|---|---|
| `X-API-Key` | کلید API همان مقصد |
| `Idempotency-Key` | شناسه‌ی یکتای پیامک (همان `id`) |

```json
{
  "id": "6f1c2e0a-8d0b-4c55-9a3e-2f5b9b1d7c11",
  "test": false,
  "sender": "+98700011",
  "bank": "ملت",
  "body": "بانک ملت\nواریز:2,500,487\n...",
  "amount": 2500487,
  "code": "487",
  "unit": "rial",
  "is_deposit": true,
  "received_at": "2026-10-08T14:20:05+03:30",
  "received_at_ms": 1791456605000,
  "attempt": 1,
  "device": "samsung SM-A515F"
}
```

- `amount` همان عددی است که در پیامک آمده (معمولاً ریال). `unit` می‌گوید ریال است یا تومان، یا `null` اگر معلوم نبود.
- `code` سه رقم آخر مبلغ است.
- `test: true` یعنی از دکمه‌ی «ارسال آزمایشی» آمده و نباید پرداختی را تأیید کند.
- هر پاسخ `2xx` یعنی رسید. پاسخ‌های `5xx`، `408`، `429` و خطای شبکه دوباره امتحان می‌شوند. بقیه‌ی `4xx` (مثلاً `401` برای کلید اشتباه) بلافاصله ناموفق ثبت می‌شوند.

### پیشنهاد برای سمت سرور

۱. `X-API-Key` را بررسی کنید.
۲. اگر `id` قبلاً دیده شده، فقط `200` برگردانید (همین جلوی پرداخت تکراری را می‌گیرد).
۳. اگر `test` بود، `200` برگردانید و کاری نکنید.
۴. سفارش در انتظاری را پیدا کنید که مبلغش دقیقاً `amount` است (با درنظر گرفتن ریال و تومان) و در چند ساعت اخیر ساخته شده. آن را پرداخت‌شده کنید.
۵. سریع جواب بدهید (زیر ۱۰ ثانیه) و کارهای سنگین را بعد از پاسخ انجام دهید.

## ساختار کد

```
app/src/main/java/app/forapp/
  core/SmsReceiver.java   دریافت پیامک، تشخیص بانک، ذخیره، ارسال فوری
  core/Forwarder.java     ارسال HTTP، تلاش دوباره، زمان‌بندی، اعلان
  core/SendJob.java       کار پس‌زمینه‌ای که فقط وقتی صف پر است اجرا می‌شود
  core/BootReceiver.java  ادامه‌ی صف بعد از روشن شدن گوشی
  core/Db.java            دیتابیس: بانک‌ها، مقصدها، پیامک‌ها، ارسال‌ها
  core/SmsParser.java     خواندن مبلغ و تشخیص واریز از متن پیامک
  core/Fa.java            ارقام فارسی و تاریخ شمسی
  ui/                     صفحه‌ها: اصلی، تنظیمات، مقصدها، ویرایش مقصد، بانک‌ها
app/src/test/             تست‌های تشخیص مبلغ و تاریخ
```

اگر قالب پیامک بانک شما درست خوانده نشد، متن آن پیامک را به `SmsParserTest` اضافه کنید و `SmsParser` را اصلاح کنید. در اپ، پیامکی که واریز تشخیص داده نشود در لاگ می‌ماند و با «ارسال دستی» فرستاده می‌شود؛ با خاموش کردن «فقط پیامک واریز» هم همه‌ی پیامک‌های آن بانک فرستاده می‌شوند.
